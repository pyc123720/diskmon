# 常见问题

先看这里，九成的「这是不是 bug」都能对上号。对不上再去开 issue。

---

## 1. 启动时 Windows SmartScreen / 杀毒软件拦我

**不是病毒，是「未知发布者」。** 项目用自签名证书构建，没有向微软累积信誉，所以 SmartScreen 一定会拦。

- SmartScreen：点「更多信息 → 仍要运行」。
- 杀软报「未知程序」：加信任/排除。
- 不想信任二进制：`build.ps1` 自己编译，一个 Go 文件树、零第三方依赖，`go.mod` 里只有 module 和 go 版本。
- 校验下载：Release 里附 `SHA256SUMS.txt`，`Get-FileHash diskmon-go.exe -Algorithm SHA256` 对一下。

> 正在走 SignPath 的开源免费签名，通过后会缓解，但信誉积累仍需要时间。

## 2. 清理完了，C 盘空间却没变大

**这是设计如此，不是没清。** 所有清理都是「移动到隔离区」，而隔离区默认就在 `%LOCALAPPDATA%\diskmon-go\quarantine`——**和 C 盘同一个卷**。同一卷内移动文件是瞬时的，但磁盘占用在移出隔离区之前不会减少。

真正释放空间有两条路：

1. 等隔离项到期（默认 7 天）自动清理；
2. 确认没问题后手动清空隔离区（「全部数据 → 隔离区」，或 `diskmon-go.exe purge`）。

这也是安全模型的代价：给你留了 7 天反悔期，代价是空间不会立刻回来。

顺带一提，以下几种情况也会让「清了但没变」：
- 文件正被程序占用，被跳过（2.5.5 起会在结果页写「跳过 N 个占用中的文件」）；
- 系统还原点 / 卷影副本吃掉了释放的空间（`vssadmin list shadowstorage`）；
- Windows 自己又写回来了（更新缓存会被重下）。

## 3. 显示「计划 4.2 GB，实际只有 12 MB」/「实际比计划还多」

先看结果页的「计划 / 实际 / 差异」明细，差异只有三种来源：

1. **实际比计划少**（最常见）：文件被占用，移不动。Chromium 的 `Cache`、微信的 `log`、Windows 的 `SoftwareDistribution` 在运行时是锁着的。结果页会写「跳过 N 个占用中的文件」。
2. **实际比计划多**：计划是开始清理时实测的，而临时文件/缓存目录在清理过程中还在写入新文件，多出来的部分是清理期间新产生的，也一并进了隔离区。
3. **两边都有**：一部分文件被锁跳过，同时目录又新写了东西，两个方向抵消后得到最终差异。

2.5.5 起：计划里会剔除已经不存在的目录；懒人清理会先采样每个目录里有多少文件被占用，页面上直接写「100% (60/60)」。
2.5.8 起：计划会在开始清理前**重新实测**（不再直接拿几小时前的扫描值）；结果逐项对账「计划 / 实际 / 差异」，上面那句话就是差异来源；清理过程中还可以**暂停 / 继续 / 停止**。

处理办法：关掉对应程序（浏览器/微信/Office）再清一次。**不要**为了清缓存去强杀系统进程。

## 4. 「谁在写盘」显示得不准

对，它是**近似值**，代码里也是这么写的。

- `USN 秒级增长`：读 NTFS 变更日志，能精确到「哪个路径涨了多少」，这个准。
- `按进程写盘量`：`GetProcessIoCounters` 给的是进程累计 I/O 计数，只能回答「谁写了多少字节」，**回答不了「谁写了哪个文件」**。

要把两者关联起来需要文件过滤驱动（类似 Process Monitor 的做法），那是另一个量级的工程和风险。工具不装驱动，所以不求精确，只求能指出「大概是它」。

## 5. 扫描很慢 / 卡

首次全盘扫描约 1–2 分钟（几十万到上百万个文件），期间是纯只读遍历。之后靠 USN 增量，基本是秒级。

如果明显超过这个量级：
- 检查是不是在扫描机械盘或网络盘（本工具为本地 NTFS 设计）；
- 看 `diskmon-go.exe diag` 里「最后一次扫描」的 `错误 N`，大量权限错误会拖慢；
- 关掉其它正在做大 I/O 的程序再试。

## 6. 能不能同时监测多个盘

不能。一次一个盘，在「设置 → 扫描根目录」里改（USN 会跟随）。多盘是计划中的功能，还没做。

## 7. 不用管理员运行会怎样

能跑，但能力降级：日志里会出现「非管理员，使用重扫模式」。

- 没有：USN 秒级归因、进程 I/O 归因；
- 还有：全盘扫描、分类、方案、隔离区、撤销、导出。

要完整体验就用管理员运行（或用安装器，它会请求 UAC）。

## 8. 会不会偷偷上传数据

不会，也没有遥测。

- 看板只监听 `127.0.0.1`，代码里只有一处 `http.ListenAndServe`；
- 没有任何出站请求（可以 grep `http.Get` / `net.Dial`，或者开着抓包跑一天）；
- 数据全在数据目录（默认 `%LOCALAPPDATA%\diskmon-go`），删掉这个目录 = 清空所有记录。

## 9. 清错了怎么还原

7 天内：看板 → 全部数据 → 隔离区（`/q`），逐项或批量还原。也可以命令行：

```
diskmon-go.exe quarantine-list
diskmon-go.exe restore <id>
```

过了保留期会被自动清理——那是唯一不可逆的动作，所以别把 `quarantine-days` 改得太短。

## 10. 和 WizTree / 火绒 / 360 有什么区别

- **WizTree / SpaceSniffer**：快，回答「现在谁最大」，靠 MFT 直接读。本工具多了「谁在长」和「可撤销的清理」。
- **火绒 / 360 的清理**：面向大多数用户，一键、规则不透明。本工具面向想搞清楚原因的人，规则可见、动作可回滚、宁可不删。
- 不是替代关系：查大头用量 WizTree 更快；查「刚刚是什么吃掉了 3 GB」用这个。

## 11. 能清 Windows.old / WinSxS / hiberfil.sys 吗

**不会自动清。** 这几类在分类里是 `adjust`：工具只告诉你多大、该用什么系统命令（`DISM /StartComponentCleanup`、`powercfg /h off`、磁盘清理），不动手。

理由：风险高、系统自带工具已经覆盖，而且清错了代价远大于收益。

## 12. 卸载残留那一页的「注册表孤立」是什么意思

扫描注册表里指向已不存在路径的卸载项/数据目录，**只提示，不自动删注册表**。给你一个线索去手动确认，删不删你自己决定。

## 13. 会不会删掉 `AppData\Local\Packages`、`WindowsApps` 这些

不会。有硬黑名单（`AppData\Local\Packages`、`Microsoft\Windows`、`WindowsApps` 等），任何规则、任何档位都不碰。

## 14. 报 bug 需要给什么

运行 `diskmon-go.exe diag`，把生成的 `diag-<时间>.txt` 贴进来。里面有版本、系统、配置、上次扫描摘要、告警、日志尾巴——一次问完，省掉三轮来回。

涉及其它问题请看 [TRIAGE.md](TRIAGE.md)（我多久回一次、什么会被关掉）。
